# 구동 계층과 검증

메가 저수준 제어 펌웨어와 Orin 기본 구동 인터페이스의 구현 및 기본 실물 구동 검증을 완료했습니다.
2026-11-12 사용자가 바퀴를 띄운 상태와 지면에서 전진·후진·좌우 회전·정지·재출발 시험을 모두 정상으로 보고했습니다.
ROS 2 속도 명령 연결과 오도메트리는 이후 단계입니다.

## 진행 순서와 확인 기준

| 단계 | 확인할 동작 | 완료 근거 |
| --- | --- | --- |
| 1. 모터·엔코더 | 좌우·전후진 부호, 목표 RPM과 실측 RPM, 출발·정지·재출발, 명령 만료 | 최신 코드 검증과 실제 바퀴 피드백 |
| 2. 차체 구동·오도메트리 | 바퀴 회전량과 실제 이동 거리·회전각의 관계, 속도 단위와 타임스탬프 | 실측 거리·각도와 오도메트리 비교 |
| 3. 센서·좌표계 | 라이다·카메라·IMU의 방향, 장착 위치, 시각과 데이터 갱신 | 정지·이동 중 센서와 TF의 일치 |
| 4. 지도·위치추정 | 수동 주행으로 지도 작성, 정지·재이동 시 위치 유지 | 실제 위치와 지도상의 위치 비교 |
| 5. Nav2 | 목표점 이동, 회전, 장애물 대응, 취소·정지 | 앞 단계에서 확인한 구동 범위 내 실제 주행 |

각 단계에서는 기존 기록의 소스와 조건이 현재 구성에 맞는지 먼저 확인합니다.
관련 변경이나 실패 근거가 없는 통과 시험은 반복하지 않습니다.
모터의 실제 응답을 확인한 뒤 상위 제어기의 속도·가속도 제한을 정합니다.

## 구동부 코드의 책임

```text
keyboard_control.py / 상위 구동 호출자
        │ 물리적 좌·우 바퀴의 목표 RPM
        ▼
wheel_drive.py (수동 조종·상위 구동 명령)
        │ 명령 수명·50 Hz 송신·측정 피드백
        ▼
motor_pid.py + drive_calibration.py
        │ 단위·채널·부호 변환, PID 설정
        ▼
motor_link.py ── serial_port.py
        │ OMR1 프레임, CRC, ACK, 텔레메트리, 시리얼 연결
        ▼
Arduino Mega: 명령 처리 → 속도 제어 → 모터 드라이버
        ▲                          │
        └──────── 엔코더 피드백 ───┘
```

- `motor_link.py`는 공통 통신 계층입니다. 모터 검사나 센서 검사 프로그램을 불러오지 않습니다. 모듈을 import하는 것만으로 장치를 열지 않습니다.
- `wheel_drive.py`는 Orin 기본 구동 인터페이스입니다. 수동 조종의 PID 경로가 이를 사용하며, 보정·진단 도구는 자기 시험 절차에 따라 `motor_link.py`를 직접 사용합니다.
- `motor_test.py`는 제한 시간 모터 시험과 결과 판정만 담당합니다. 기존 호출자를 위해 통신 클래스·함수 이름도 계속 제공합니다.
- `drive_calibration.py`가 물리적 좌우 바퀴와 원시 채널·부호 사이의 변환을 담당합니다.
- `motor_pid.py`가 검증된 설정 로딩, RPM·rad/s 변환과 측정 피드백 해석을 담당합니다.
- `keyboard_control.py`가 키 입력, 목표 갱신과 조종 중 정지 요청을 담당합니다.
- Mega가 속도 PID와 엔코더·명령 만료·출력 한도 감시를 수행합니다. 호스트에서 PID를 중복 실행하지 않습니다.

## 명령과 피드백의 계약

| 항목 | 의미 |
| --- | --- |
| 물리적 바퀴 속도 | 전진을 양수로 하는 좌·우 RPM. ROS 경계에서는 rad/s를 명시적으로 변환 |
| `SET_SPEED L R lease_ms` | 드라이버 L/R 순서의 0.01 RPM 값. 명령 유효기간은 100–300 ms |
| 원시 엔코더 순서 | 오른쪽 D40/41, 왼쪽 D50/51 |
| 속도·PWM 순서 | 드라이버 L/M2, R/M1 |
| 위치 피드백 | 수신 엔코더 카운트를 누적한 실제 측정값 |
| `SET_SPEED 0 0` | 0 RPM 제어. 설정에 따라 정지 위치 유지(HOLD) |
| `STOP` | 제어와 출력을 해제. 기존 오류는 유지 |
| 목표 갱신 | 통신상의 명령 유효기간은 갱신하되, 같은 방향의 속도 변경으로 고장 감시 누적을 지우지 않음 |

명령 수락(ACK)과 실제 정지는 서로 다른 상태입니다. 정지 확인에는 새 측정값과 제어 상태를 사용합니다.
엔코더와 속도 배열의 순서가 다르므로 상위 코드에서 원시 배열을 임의로 같은 인덱스로 결합하지 않습니다.

## Orin 기본 구동 인터페이스

`WheelDrive`는 이미 연결되고 PID 설정을 적용한 `MotorClient`를 받습니다.
시리얼을 소유하는 한 스레드에서 수신(`client.poll`)과 구동 갱신을 수행합니다.

| API | 동작 |
| --- | --- |
| `set_target_rpm(left, right)` | 물리적 좌우 바퀴 목표를 받아 생성 시각을 저장. 전진 양수, RPM 단위 |
| `tick()` | 새 피드백을 확인하고 최대 50 Hz로 목표 전달. 명령 생성 시각은 갱신하지 않음 |
| `stop()` | 즉시 0 RPM 목표를 적용. 지속적인 HOLD에는 새 0 명령 공급 필요 |
| `disable()` | `STOP`으로 출력 해제하고 이전 목표 삭제. 오류 자동 해제 없음 |
| `feedback()` | 메가가 보고한 목표·측정 RPM, 실제 누적 엔코더·라디안 위치, PWM, 오류와 데이터 나이 반환 |

마지막 입력이 300 ms를 넘으면 출력을 해제합니다. 재전송할 때도 원래 명령의 남은 시간만 메가 유효기간으로 사용합니다.
메가가 허용하는 최소 유효기간 100 ms보다 적게 남으면 재전송을 멈춥니다.
피드백이 400 ms 동안 갱신되지 않거나 메가 오류·전송 실패가 있으면 `STOP`을 시도하고 해당 구동 객체의 재사용을 차단합니다.
속도는 보정 상한 안의 유한한 값만 허용하며, 작은 목표를 임의로 30 RPM까지 올리지 않습니다.

키보드의 한 번 입력 후 유지 방식은 조종기가 현재 선택 방향을 매 반복마다 새 의도로 공급하는 방식으로 유지합니다.
키보드 프로그램 자체가 멈추면 메가의 명령 유효기간도 만료됩니다.
오도메트리 적산과 ROS 노드 연결은 이후 단계이며, 이 계층에서는 측정 바퀴 상태를 제공합니다.

## 기존 자료를 해석하는 기준

현재 로컬 `config/motor_pid.json`은 2026-11-05의 무부하 보정 자료입니다.
주요 목표는 30–95 RPM이며, 곡선 조건에는 한쪽 바퀴 15 RPM 측정도 포함됩니다.
`tools/motor_pid.py`에는 당시 10 RPM에서 불안정했다는 주석이 있습니다.
이는 현재 지면 조건에서 가능한 최소 속도를 확정하는 근거가 아닙니다.

조종기의 선택 속도 하한 30 RPM은 UI 제한입니다. `velocity_commands()`는 그보다 작은 목표도 전달할 수 있습니다.
작은 명령을 전달할 수 있다는 사실과 그 속도에서 실물이 안정적으로 움직인다는 사실을 구분합니다.
배포할 때는 로봇에서 실제 사용하는 보정값을 보존합니다.
2026-11-12 확인한 기존 제어 폴더와 실물 시험 폴더의 보정 파일은 모두 일치했습니다.
개발 PC의 설정을 로봇에 설치된 최신 설정으로 간주하지 않습니다.

## 오프라인 검증

실제 Mega 타깃 빌드는 업로드 없이 수행합니다.

```bash
./mega_firmware.sh build
```

펌웨어를 수정한 경우에만 위 빌드를 수행하고, 변경한 동작과 직접 연결되는 검사를 선택합니다.
기존에 통과한 전체 검사를 매번 반복하지 않고, 변경한 동작에 필요한 검사만 선택합니다.

이번 Orin 구동 계층의 검증 범위는 목표 변환·송신 주기·명령 만료·측정 피드백·오류 시 정지와 기존 수동 조종 연결입니다.

```bash
PYTHONPATH=tools:tests /usr/bin/python3 -m unittest \
  test_wheel_drive \
  test_keyboard_control.ControllerTests.test_pid_in_place_limit_preserves_selected_forward_speed \
  test_keyboard_control.TerminalIntegrationTests.test_default_pid_targets_curve_stop_and_sigterm
```

이번 Orin 계층은 위 선택 검사 6개를 한 번 실행해 통과했습니다(2026-11-11, 4.700초).
가상 시계와 가상 시리얼을 사용했으며, 검증 대상 파일의 전후 일치도 별도 확인했습니다.

첫 구조 정리의 이력: Mega 빌드와 88개 테스트를 통과했습니다.
Flash 사용량은 27,614 B, RAM은 2,225 B이며, 빌드·검증 전후 소스와 설정의 해시가 동일함을 확인했습니다.
실행 로그는 개발 워크스페이스의 `reports/restart_offline_20261111/`에 보관하며 Git에 포함하지 않습니다.

## 기본 실물 구동 검증

2026-11-12 사용자가 최신 검사용 소스를 Orin에 반영하고 메가 업로드 절차를 수행한 뒤, 안내된 기본 구동 시험 결과가 모두 정상이라고 보고했습니다.

| 조건 | 확인 결과 |
| --- | --- |
| 바퀴를 띄운 상태 | 전진·후진·제자리 좌우 회전과 정지 정상 |
| 지면 | 출발·전진·후진·좌우 회전·정지·재출발 정상 |
| 배포 소스 | 개발 PC의 구동 코드·펌웨어 소스가 Orin의 실물 시험 폴더와 해시 일치 |
| 보정값 | 기존 제어 폴더와 실물 시험 폴더의 보정 파일 일치 |

실물 동작 결과는 사용자 보고이며, 소스와 보정 파일의 일치는 SSH로 확인했습니다.
이 시험은 기본 구동 확인으로, 통신 단절 시 차단 시간이나 정지 거리의 계측 결과를 포함하지 않습니다.
